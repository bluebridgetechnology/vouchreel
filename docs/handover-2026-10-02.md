## 2. Rules the codebase now enforces (do not undo)

`npm run lint` (ESLint **plus** `scripts/check-tokens.mjs` and `scripts/check-contrast.mjs`) fails the build on:

- raw Tailwind palette classes (`bg-emerald-500`, `text-white`), hex/`rgb()`/`hsl()` literals in TSX, arbitrary text sizes (`text-[11px]`), `font-semibold/bold` (Outfit max weight is 500), legacy radius (`rounded-md/lg/xl/full`), shadcn alias classes (`bg-card`, `text-muted-foreground`, `bg-primary`)
- hand-rolled `<button>/<input>/<select>/<textarea>` (use `Button`/`buttonVariants`, `toggleStyle`, `Switch`, `Input`/`inputClass`; `live-preview.tsx` and `theme-toggle.tsx` are allowlisted)
- `alert()` / `confirm()` (use `notify.*` from `lib/notify.ts` and `useConfirm()`)
- any semantic colour pair that falls below WCAG AA (62 pairs, light + dark)

Conventions (full text in `AGENT.md` section 13):

- Tokens live in `apps/dashboard/app/globals.css`; use `bg-surface`, `text-text-muted`, `bg-brand`, `rounded-card`, `rounded-pill`, etc. Reference page: `/design` (dev only).
- Headlines are Outfit. Playfair Italic only for 1-2 emphasised words via `<Em>`.
- Icons: `<Icon name="..." />` (Solar Outline, server-rendered, offline subset). Add names in `apps/dashboard/scripts/build-icons.mjs`, then `npm run icons:build -w apps/dashboard`.
- User-chosen colours (widget theme, collect accent, social brand colour) are data: `userAccentStyle()` + `bg-(--user-accent)`. Server defaults use `DEFAULT_BRAND_HEX` (`#cf3d0b`) from `lib/brand.ts`. Changing `--palette-coral-600` requires updating `DEFAULT_BRAND_HEX`, the widget `--vr-primary`, and the DB default (tests catch drift).
- Every route that fetches has a `loading.tsx` built from `components/ui/page-skeleton`; async buttons use `<Button loading>`.
- Plan limits come from the **database** (`plans.limits`, `-1` = unlimited) via `getSubscriptionLimits`; never hardcode limits. Anything that creates a testimonial must call `enforceTestimonialLimit(spaceId)`.
- Platform admin = `isPlatformAdmin(user)` only. Never derive it from `user.role` (every account is "owner" of its own workspace).
- Outbound fetches of user-supplied URLs must use `assertPublicUrl` / `safeFetch` (`lib/security/ssrf.ts`).
- Client IP for rate limits: `getClientIp(headers)`; rate limit with `await rateLimit(key, opts)`.
- Platform admin actions are written to `admin_audit_log` via `logAdminAction`.

## 3. Running it locally (Windows)

- **Postgres** is the Windows service `postgresql-x64-18`. If it is stopped (after a reboot) start it from an **Administrator** PowerShell: `Start-Service postgresql-x64-18`. (`npm run db:start` is the Docker alternative; Docker Desktop is not installed at the default path.)
- **FFmpeg** was installed with `winget install Gyan.FFmpeg`. Open a **new terminal** so PATH picks it up (or set `FFMPEG_PATH`). Check `GET /api/health` -> `{"status":"ok","checks":{"database":true,"ffmpeg":true,"captions":true}}`.
- `npm install`, then `npm run db:migrate` (PowerShell: run it through npm, `db:migrate` alone is not a command), `npm run widget:build`, `npm run dev` (app on `http://localhost:3000`).
- Seeded demo account: `demo@vouchreel.com` (password is in `apps/dashboard/scripts/seed-demo-user.mjs`). It has been granted platform admin in the local DB. Grant others with `npm run admin:grant -w apps/dashboard -- you@company.com` (`--revoke` to remove).
- Migrations applied locally: 0009-0014 (brand default, platform-admin flag, `submissions.processing_error`, notifications tables, plan limits + audit log). Production must run `db:migrate` before deploy.

### Pre-deploy env checklist

`CRON_SECRET` (required, cron returns 503 without it), `TRUSTED_PROXY_HOPS` (match your proxy chain), `UPSTASH_REDIS_REST_URL/_TOKEN` (needed on Vercel / multiple replicas), `RESEND_API_KEY` + `EMAIL_FROM`, then the usual DB/auth/storage/payment vars. Details in `docs/deployment.md` ("Security and operations checklist"). Video processing cannot run on Vercel (no FFmpeg).

### B. Next feature: AI video from text testimonials (design already agreed)

**Goal:** turn a written testimonial into a short video usable on the site and in the widget.

**Approach: motion-graphic quote videos with synthetic voiceover. No fake face of the customer.**

1. Trim the real text for length only (never change the meaning; show a diff and require approval).
2. Text-to-speech (ElevenLabs or OpenAI) for the voiceover; reuse `testimonial_translations` to voice translated text.
3. Render animated typography on brand templates (Remotion, or extend the existing ffmpeg social pipeline in `lib/social/pipeline.ts`), 9:16 and 16:9, with captions.
4. Store as a `generated` video attached to the testimonial; the widget plays it like any other.
5. Optional later: branded/abstract presenter avatars (HeyGen); A/B test generated vs real video with the existing experiments feature.

**Legal and trust guardrails (non-negotiable):** the FTC's 2024 rule bans fake or misleading AI-generated reviews. Therefore: only generate from real customer-submitted text; add a **consent checkbox** on the collect form; show a visible **"AI-generated from a written review"** label in the widget; never synthesise a likeness or cloned voice of the real person.

**Build shape:**
- Provider interface like `lib/payments` and `lib/translations` (mock provider as default so dev/tests need no keys).
- `generated_videos` table: testimonial id, status, template, voice, script (original + trimmed), cost, consent id, output URL.
- Credits metered per plan: add the credit allowance to `plans.limits` and the admin plan form.
- **Prerequisite:** a durable job queue/worker (item A2). Start there or the feature will fail on restarts.
- Rough MVP: 3 templates, 2 voices, captions, consent + label, credits. Estimate 2-3 weeks.

## 6. Verification habits that worked

- Run the same commands CI runs: `npm run lint`, `npm test`, `npm run widget:build`, `npm run build` (from the repo root). Remember CI builds **without a `.env` file**; test builds with `.env` files moved away when touching env handling.
- For anything touching auth, plans, limits, notifications, or admin, verify live (sign in via `fetch('/api/auth/sign-in/email')` in the browser pane, then exercise the API). Several real bugs were only found this way or by writing the test first (e.g. partial plan updates injecting Zod defaults).
- Before merging a PR, check `gh pr checks <n>`. A failing check on PR #7 was a real bug, not noise.

## 7. Tooling gotchas for the assistant

- In this environment, **large Bash heredocs that contain quotes or backslashes can fail to parse or silently lose backslashes**. For files with regexes or escapes, create them with the Write/Edit tools; for scripted edits, write a Python file and run it.
- The browser pane's screenshots time out when the window is hidden; retry, or verify through the DOM with `javascript_exec`. `javascript_exec` cannot span a navigation.
- Git: the user's uncommitted root `package.json` blocks branch switches. Use `git stash push package.json` ... `git stash pop`. Never commit it, `AGENTS.md`, `CLAUDE.md`, or `seed-demo-user.mjs` without asking.
- Merging PRs needs the user's explicit instruction each time (an earlier merge was blocked by the permission classifier when it was not explicit). Retarget stacked PRs to `main` before merging.
- The user prefers terse answers, a verified summary at the end of each task, and being told what was *not* verified.
